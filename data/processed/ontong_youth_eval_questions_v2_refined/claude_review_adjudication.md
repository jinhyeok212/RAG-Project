## 2. 조정에 사용한 합의 루브릭

당신이 V1 피드백에서 정리한 **질문 2분류**를 그대로 축으로 삼되, 검색 평가에서 결과가 완전히 달라지는 세 가지 결함을 분리했다.

### 2-1. 질문 유형 (당신의 프레임 채택)

| 유형 | 해당 question_type | 정책명·고유명사 노출 | 필수 조건 |
|---|---|---|---|
| **정책 발견형** | `specific_policy_search` | 금지 | 질문만으로 정답 문서가 특정될 만큼의 조건(지역+대상+분야+특징) |
| **정책 정보 조회형** | `support_content` / `eligibility` / `application_method` / `application_period` / `required_documents` | **허용, 오히려 권장** | 정책이 식별될 것 + 물어본 항목의 답이 문서에 있을 것 |

"정책명이 들어갔으니 무조건 0"이라는 내 V1식 기준은 폐기했다. 실제 사용자는 "청년창업 특례보증 필요서류가 뭐야?"라고 묻고, 그건 정상적인 평가 질의다.

### 2-2. 결함 3분류 (내가 추가한 축)

| 코드 | 결함 | 판정 | 이유 |
|---|---|---|---|
| **A. 관련성 오류** | 정답 문서가 질문에 답하지 못함 (혜택유형·대상·지역 불일치) | **0** | 측정 대상 자체가 틀림. 어떤 후처리로도 복구 불가 |
| **B. qrels 불완전** | 정답 문서는 답하는데 같은 조건을 만족하는 문서가 더 있음 | **2** | IR에서 말하는 incompleteness. 정답을 추가하거나 질문에 슬롯 1개를 넣으면 복구됨 |
| **C. 질의 결함** | 문장 파손, 동일 질문·다른 정답 | **0** | 문장을 새로 써야 함 |

**핵심 논리: A와 B는 결과가 다르다.** A는 RAG가 정답을 맞혀도 틀렸다고 채점되는 구조적 오류라서 버려야 한다. B는 RAG가 "다른 맞는 문서"를 가져와서 손해를 보는 것이라 **정답 목록을 늘리면 해결된다.** 나는 B를 A처럼 취급해 23건을 과잉 폐기했고, 당신은 B를 무결점으로 취급해 그대로 통과시켰다. 둘 다 틀렸다.

### 2-3. 최종 판정 규칙

```
정답 문서가 질문에 답하지 못한다        → 0
질문 문장이 깨졌거나 중복 질문의 열위 쪽 → 0
답하지만 경쟁 문서 존재, 슬롯 1개 추가나
   다중 정답 지정으로 복구 가능          → 2  (복구 방법을 명시)
답하고 이미 정답이 유일하다              → 1
```

### 이 33건이 알려주는 것

라벨 2의 **33건 중 26건이 정책 정보 조회형**이다. 즉 V2의 최대 실패는 "질문이 포괄적"이라는 막연한 문제가 아니라, **정보 조회형 질문인데도 정책명 금지 규칙을 적용해 정책을 식별할 단서를 전부 지워버린 것**이다. 당신이 V1 피드백에서 정리한 2분류가 정확히 이 지점을 짚는다.

## 8. V3 규칙 (조정 결과 반영)

1. **질문 유형을 먼저 정하고 규칙을 분기한다.**
   - 정보 조회형(80%): 정책명 또는 그에 준하는 식별 슬롯을 **반드시** 넣는다. 정책명 노출 금지 규칙은 여기 적용하지 않는다.
   - 발견형(20%): 정책명 금지 유지, 대신 지역+대상+분야+**특징** 4슬롯을 모두 채우고, 못 채우면 생성하지 않는다.
2. **혜택유형 슬롯은 `plcySprtCn` 본문에서 검증된 값만 사용한다.** 최종 0의 41건이 이 검증 하나로 걸러진다(q0019 대출·보증, q0041 교육, q0050 건강, q0067 대출 등).
3. **대상 슬롯도 `ptcpPrpTrgtCn`/`addAplyQlfcCndCn`로 검증한다.** q0055(재학생 지원 불가), q0088(참전국 인재), q0008(사업장 대상), q0089(대학교 대상)가 모두 여기서 걸린다.
4. **지역은 `zipCd` 매핑으로만 만들고 화이트리스트를 통과시킨다.** `자격시`, `출퇴근시`, `건설도시`, `지역기구` 같은 토큰 7건 방지. 또한 이 corpus는 광주·전남이 같은 코드로 묶여 있으므로 **광역 단위 지역 슬롯은 유일성 근거로 쓰지 않는다**(q0083 사례).
5. **생성 직후 자동 검사 3종을 통과한 것만 후보로 남긴다.**
   - 중복 검사: 동일 질문 텍스트가 서로 다른 정답을 갖는 조합 금지
   - 유일성 검사: BM25(char 2-gram) 상위 3위 안 + 2위와 점수 차 확보. 상위권에 형제 문서가 붙으면 **다중 정답으로 자동 승격**
   - 근거 검사: 질문 유형에 대응하는 필드가 40자 이상이고 "공고문 참조" 류가 아닐 것
6. **corpus 중복 문서를 먼저 정리한다.** 제목 동일 8그룹 17건 + 내용 유사쌍은 dedup 하거나 qrels에 형제 문서를 함께 넣는다.
7. **목표 건수를 채우려 하지 말 것.** 검사를 통과한 것만 남기고, 부족하면 문서를 바꿔 재시도한다.
