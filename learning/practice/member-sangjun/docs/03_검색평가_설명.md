# 03_evaluate_retrieval.py 설명

이 단계는 질문을 넣었을 때 FAISS가 정답이 들어있는 청크를 잘 찾아오는지 평가합니다.

## 이 단계가 하는 일

```text
eval_questions.csv
-> question을 임베딩
-> FAISS에서 비슷한 청크 Top-k 검색
-> 검색된 청크 안에 answer가 있는지 확인
-> 결과 CSV 저장
```

## Top-k란?

Top-k는 가장 비슷한 검색 결과를 몇 개 가져올지 정하는 값입니다.

예를 들어 Top-k가 3이면 가장 비슷한 청크 3개를 가져옵니다.

```text
Top-k 3 = 검색 결과 3개
Top-k 5 = 검색 결과 5개
```

Top-k가 커지면 정답이 포함될 가능성은 올라갑니다.

하지만 너무 많이 가져오면 불필요한 문서도 같이 들어옵니다.

## 평가 기준

처음 평가는 단순하게 합니다.

```text
검색된 Top-k 청크 안에 answer 문자열이 있으면 성공
없으면 실패
```

예시:

```text
질문: 이번 포럼의 주제는?
정답: 청소년과 뉴미디어

검색 결과:
이번 포럼의 주제는 '청소년과 뉴미디어'다.

평가: 성공
```

이 방식은 완벽한 평가는 아니지만, RAG 검색 단계를 이해하기에는 충분합니다.

## Recall이란?

이 프로젝트에서 Recall은 다음 뜻입니다.

```text
전체 질문 중 정답이 검색 결과 안에 들어온 비율
```

예를 들어 질문 30개 중 24개가 성공하면:

```text
Recall = 24 / 30 = 0.8 = 80%
```

300자 청크, Top-k 3:

```bash
python src/03_evaluate_retrieval.py --index-dir vector_store/faiss/chunk_300 --top-k 3
```

300자 청크, Top-k 5:

```

700자 청크, Top-k 3:

python src/03_evaluate_retrieval.py --index-dir vector_store/faiss/chunk_700 --top-k 3
```

700자 청크, Top-k 5:

```bash
python src/03_evaluate_retrieval.py --index-dir vector_store/faiss/chunk_700 --top-k 5
```

## 출력 파일

결과는 `outputs` 폴더에 저장됩니다.

```text
retrieval_results_chunk_300_top_3.csv
eval_summary_chunk_300_top_3.csv
```

상세 결과 파일에는 질문별 검색 결과가 들어갑니다.

요약 결과 파일에는 전체 Recall이 들어갑니다.
