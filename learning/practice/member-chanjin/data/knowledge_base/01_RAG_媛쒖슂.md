# 01. RAG 개요

## RAG란?

RAG는 Retrieval-Augmented Generation의 약자다. 한국어로는 보통 검색 증강 생성이라고 부른다. 핵심 아이디어는 대규모 언어 모델이 내부 지식만으로 답변하지 않고, 외부 문서에서 관련 정보를 먼저 검색한 뒤 그 근거를 바탕으로 답변을 생성하는 것이다.

LLM은 학습 시점 이후의 정보나 조직 내부 문서, 최신 정책, 프로젝트 문서처럼 모델 학습에 포함되지 않은 지식에 약하다. RAG는 이런 한계를 줄이기 위해 문서 검색 시스템과 LLM을 결합한다.

## RAG가 필요한 이유

1. 모델이 모르는 내부 지식을 답변에 반영할 수 있다.
2. 답변 근거가 되는 문서를 함께 보여줄 수 있다.
3. 문서가 바뀌면 모델을 다시 학습하지 않아도 지식베이스만 업데이트할 수 있다.
4. Hallucination, 즉 근거 없는 답변을 줄이는 데 도움을 줄 수 있다.
5. 검색 로그와 답변 로그를 남기면 품질 모니터링이 가능하다.

## RAG의 기본 구조

사용자 질문이 들어오면 RAG 시스템은 다음 순서로 동작한다.

1. 질문을 임베딩하거나 검색 쿼리로 변환한다.
2. 벡터 DB 또는 검색 인덱스에서 관련 문서 chunk를 찾는다.
3. 검색된 문서들을 프롬프트에 넣는다.
4. LLM이 질문과 검색 문서를 함께 보고 답변을 생성한다.
5. 답변, 검색 문서, 지연시간, 토큰 수, 비용, 평가 점수를 로그로 저장한다.

## RAG와 일반 챗봇의 차이

일반 챗봇은 모델이 알고 있는 지식에만 의존하는 경우가 많다. 반면 RAG 챗봇은 외부 문서 검색 결과를 답변 근거로 사용한다. 그래서 회사 내부 매뉴얼, 정책 문서, 고객 FAQ, 분석 리포트, 장애 대응 문서처럼 계속 바뀌는 지식에 적합하다.

## 팀 프로젝트에서 RAG를 이해할 때 중요한 관점

RAG는 단순히 “문서를 넣고 챗봇이 답한다”로 끝나지 않는다. 실제 운영에서는 검색 품질, 답변 품질, 응답 속도, 비용, 실패율을 함께 관리해야 한다. 따라서 RAG를 만들 때는 검색 파라미터와 생성 파라미터가 어떤 영향을 주는지 이해해야 한다.
