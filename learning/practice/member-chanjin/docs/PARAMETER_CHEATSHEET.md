# RAG 파라미터 치트시트

## chunk_size

- 의미: 문서를 나누는 크기
- 왜 조정하는가: 문맥 충분성, 검색 정밀도, 비용 균형을 맞추기 위해
- 너무 작으면: 문맥 부족, 답변 근거 부족
- 너무 크면: 노이즈 증가, 토큰 비용 증가, latency 증가
- 실습 추천: 500~800자

## chunk_overlap

- 의미: chunk 사이에 겹치게 둘 문장/글자 수
- 왜 조정하는가: 문서 경계에서 핵심 문맥이 잘리는 것을 방지하기 위해
- 너무 작으면: 문맥 단절
- 너무 크면: 중복 chunk 증가, 비용 증가
- 실습 추천: 80~150자

## top_k

- 의미: 검색 결과를 몇 개 가져올지
- 왜 조정하는가: 필요한 근거 문서를 놓치지 않으면서 노이즈와 비용을 줄이기 위해
- 너무 작으면: 정답 문서 누락 가능
- 너무 크면: 관련 없는 문서 포함, prompt token 증가
- 실습 추천: 3~5

## similarity_threshold

- 의미: 검색 결과로 인정할 최소 유사도
- 왜 조정하는가: 관련 없는 문서를 줄이기 위해
- 너무 낮으면: 노이즈 문서 증가
- 너무 높으면: 필요한 문서도 검색에서 제외
- 실습 추천: TF-IDF 기준 0.05부터 시작

## retrieval_mode

- Top-k: 관련도 높은 순서로 가져옴
- MMR: 관련도와 다양성을 함께 고려
- 왜 조정하는가: 중복 chunk를 줄이고 다양한 근거를 확보하기 위해
- 실습 추천: 기본은 Top-k, 문서가 많고 중복이 많으면 MMR

## mmr_lambda

- 의미: MMR에서 관련성과 다양성의 균형
- 1에 가까움: 관련성 중심
- 0에 가까움: 다양성 중심
- 실습 추천: 0.5~0.8

## retriever_backend

- TF-IDF: 설치가 쉽고 빠름, 키워드 기반
- Sentence-Transformers: 의미 기반 검색에 강함, 모델 다운로드 필요
- 왜 조정하는가: 키워드 검색과 의미 검색의 차이를 비교하기 위해

## temperature

- 의미: LLM 답변의 무작위성
- 왜 조정하는가: 답변 일관성과 창의성의 균형을 맞추기 위해
- RAG 추천: 0.0~0.3
- 너무 높으면: 근거 없는 답변 가능성 증가

## max_tokens

- 의미: 생성 답변의 최대 길이
- 너무 작으면: 답변이 끊김
- 너무 크면: 비용 증가, 장황한 답변
- 실습 추천: 500~1000

## prompt_version

- 의미: 프롬프트 템플릿 버전
- 왜 필요한가: 프롬프트 변경 전후 품질, 비용, hallucination 비율을 비교하기 위해
- 최종 프로젝트에서는 반드시 로그에 저장해야 함
